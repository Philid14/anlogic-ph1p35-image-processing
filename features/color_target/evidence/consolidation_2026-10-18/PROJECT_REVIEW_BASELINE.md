## 1. 给首次接触项目者的背景

整体项目面向安路 PH1P35MDG324 FPGA 的相机采集、图像处理和 HDMI 显示，目标显示规格至少 1280×720@60Hz，并需保持安路 Logo、视频完整性和长期稳定。
本轮负责 TARGET：观察已有彩色流，按指定颜色检测目标，给出匹配像素数、包围框、包围框中心与帧身份，再形成跟踪状态、框线和坐标文字。
MAIN 负责真实 MIPI/ISP/DDR/HDMI 接线、时钟、复位、约束、共享 OSD、完整构建和上板；LATENCY 是另一项独立分工。
以下结论不代表另一条 system 工程线或 MAIN/LATENCY 的最新整机进度。

输入契约：RGB888、96bit、每有效时钟 4 像素，lane0=[95:72]，从左到右；无 ready，不允许以反压拖慢视频。坐标是原图坐标，默认 1280×720。
SOF/EOL/EOF 分别指首有效拍、行末有效拍和帧末有效拍；每帧携带 32bit session_id 和 32bit frame_id。
输出是一个全局包围框，不是多个物体；中心是框的中点，不是像素质心，匹配数不是置信度。

当前独立实验路径：RGB分类 → 可选中心支持过滤（默认关闭）→ 固定光栅统计 → 基础跟踪 → 框/十字与文字覆盖请求。
兼容路径仍保留原 color_target_detect；新 color_target_detect_stream 是独立实验封装，尚未替换主线。

## 3. 已复现并修复的问题

### 3.1 文字字段混合发布

原逻辑分轮转换 count/X/Y，并在不同时间读入字段，状态和明暗又直接跟随输入。更新落在转换期间时，新 count 可能配旧坐标，忙时输入还可能污染同一组数字。
修复为开始时快照整组输入、转换期间暂存、最后整组同拍发布。旧 RTL 被动态回归抓出 4036 个不一致采样；修复后 7962 拍无不一致。
一组转换 70 拍，最新稳定输入最多 140 拍可见，中间变化允许合并。它解决字段事务一致性，尚未解决显示帧一致性。

### 3.2 RTL RAM 行为与厂商原语不同

3×3 窗口要读取旧行并写入新行；初版依赖混合端口同地址读写的返回值。RTL 模型通过，但厂商原语功能仿真失败，上一帧末行边缘被误删。
修复为读后下一拍写，并对一拍宽度显式转发，消除同址读写新/旧值依赖。该经验说明后续任何标签 RAM/候选表也需核查真实端口语义。

### 3.3 统计关键路径过长

初版串行处理四 lane 的 min/max，再组合到中心坐标，TD 显示 16 级关键路径；10ns 人工约束下旁路/过滤 SWNS 为 -3.157/-3.788ns。
利用固定光栅每拍四像素对齐，优先编码最左/最右命中 lane，减少串行比较。之后的分类资源优化完成后，最终同架 SWNS 为 +1.170/+1.140ns。
这是独立 gate 估计，未证明真实频率或布线后时序。

### 3.4 常数乘法占用 DSP

原先推测常数乘法会被综合成移位加法；TD 实际映射为每 lane 两个 DSP，四 lane 共 8 个。
显式写出数学等价移位加减后，同架实测 0 DSP，分类回归通过；相对优先编码中间版本增加约 130 LUT，并消耗部分时序裕量。因此这是资源取舍，不是所有指标同时改善。

### 3.5 EOF 后重复发布上一帧

旧检测器 EOF 发布后未关闭帧状态；正常 4 像素单拍帧后再来一个无 SOF 的 EOF，count 从 4 累加为 8，并错误发布为有效。
新增独立硬期望，先证明旧 RTL 失败，再于 EOF 关闭帧。正常单拍、连续帧、abort 后恢复及完整帧回归通过。该问题已修复于当前提交。

## 4. 待解决问题、完整因果链与评审切入点

### 4.1 实拍数据缺失，颜色与最小目标边界不能确定【最高优先级依赖】

事实：目前 RGB 全链输入为合成控制，没有已确认的相机保留集；用户要求相关结论等实际素材。
链条：理想等比例 RGB 缩放下色相可保持 → 实际 AWB 是不同通道增益，暗部还受量化/噪声影响 → 当前绝对彩度 C=max-min 与亮度门限也可能让暗目标退出 → 框可能碎裂、偏移或消失 → 放宽门限又增加背景误检。
当前颜色默认 W=30°、C_MIN=24、V_MIN=32，MIN_COUNT=64；它们不是本轮实拍调优结论。
优化与验收：取得风格化前、可追溯 ISP 配置的 RGB 序列，按场景/光照/物体划分调参与保留集；同时统计漏检、误报、框 IoU、中心误差与恢复时间，不能只报平均 IoU。
请专家建议：实际必须支持的光照/白平衡变化和最小宽度/面积/形状是什么，哪些场景可明确排除？

### 4.2 多个同色对象时没有目标选择定义【需求先于算法】

事实：所有命中像素归入一个全局框，未进行组件分离。
链条：两个分离同色对象同时出现 → 全局 min/max 包住两者及中间背景 → 框中心可能落在空白处 → 后级只有一个合并结果，基础跟踪无法恢复对象身份 → 直接改成最大域又会选中更大的干扰物。
优化与验收：先确定“全部同色区域”还是“一个指定对象”；若是单对象，明确冷启动、消失重现、大小交叉和遮挡时的选择规则，再评估候选分离。
请专家建议：目标是最大、最近历史位置、指定 ROI/形状，还是外部选择？冷启动没有先验时凭什么唯一确定目标？

### 4.3 全局框对离群点敏感，轻量去噪有明确副作用【算法尚未闭合】

事实：support3 保留中心命中且 3×3 至少 3 命中的像素。它删除孤立点，但保留 2×2 噪团，削短一像素细线端点。
链条：全局极值统计对远处少量点敏感 → 孤立点可撑大框 → 中心支持过滤消除部分离群点 → 密集小噪团仍通过 → 加强邻域过滤又可能抹去真实细目标；单调加大过滤强度不能同时满足全部目标。
合成配对证据：孤立点组 6 帧 IoU 约 0.0228→1；细线组 4 帧 1→0.875；空场景噪团组两模式均误报 4/4。它们是设计的控制，不是相机统计。
优化与验收：结合最小目标约束比较完全旁路、支持过滤和候选级筛选，分别报告收益与退化，保持同帧/同预算比较。过滤仍默认关闭。
请专家建议：允许损失多少细目标边界？实际噪声更像孤立点、成团噪声还是同色背景？

### 4.4 观察流的 EOF、坐标和异常定义尚未落到 MAIN【接入阻塞项】

事实：主线所查 uial2axis 的 tlast 是 EOL，tuser 与首有效像素相符；现有模块需要真正的帧 EOF。
链条：若把 EOL 当 EOF → 每行都结算为一帧 → 统计、身份和跟踪确认次数全部失真；若坐标/标签与 RGB 偏一拍 → 窗口和框错位，或新统计器把完整帧作废。
优化与验收：MAIN 从核实的时序生成 EOF、原图坐标及稳定身份；注入丢拍、提前 SOF、错 EOL、最后四 lane 目标，检查每帧事件数和无效原因。
请专家建议：错误能在何时可靠获知？abort 是坏帧结束通知还是可能发生在任意空闲拍？截断由谁检测？

### 4.5 结果可用时间与显示帧身份尚未闭合【核心系统难点】

事实：整帧统计要等 EOF；新封装旁路 EOF+1 拍、过滤 EOF+323 拍才发布，track 再晚一拍，文字另需转换。
链条：显示可能已在读取某缓存帧 → 对应检测结果尚未完成或已被后续结果覆盖 → 直接使用“最新框”会把帧 n 的图像与帧 n±1 的结果混合 → 画面上看似抖动或漂移，算法本身可能完全正确。
HOLD 又刻意保留历史框身份；DDR 槽位复用后，槽号不是唯一帧身份。框更新快于文字时，还可能出现框和文字分别属于不同观测。
优化与验收：像素缓存携带 session/frame 和写入代次；选帧时锁存元数据；显示边界锁存一致的结果组合；明确结果缺失/晚到时隐藏、延迟显示或带年龄使用旧结果。需验证跳帧、重复显示、槽位覆盖和复位。
请专家建议：是否必须同帧精确标注？现有读出策略给结果多少时间？能接受的图像延迟和历史框显示语义是什么？

### 4.6 跨时钟域缺少整组传递与服务能力契约【核心系统难点】

事实：观察域与 HDMI 显示域不同；当前独立回放为同域，未实现 CDC。
链条：单拍 ready 脉冲可能被另一时钟域漏采 → 单独同步每个坐标位又可能拼出跨帧字段 → 即使采用握手，源端若在应答前覆盖负载仍会错包 → 若选择 FIFO，又需处理满、复位和在途数据。
优化与验收：明确握手/FIFO 的所有者、源端保持期、最大事件率/接收停顿、复位代次、满时策略；检查事件恰好一次、顺序、负载一致和视频永不被反压。是否需要队列取决于真实服务时间，不能预先宣称一个握手一定够。
请专家建议：显示侧最长多久不接收？丢弃中间显示更新是否允许？结果事件流和显示帧查表应怎样分工？

### 4.7 截断恢复必须显式复位，可能取消前一帧在途结果【恢复策略待定】

事实：过滤器依赖固定光栅计数、行 RAM 与 EOF 自动排空；完整错误帧可无效发布，真正截断需外部复位。
链条：帧中途缺失后无法仅靠内部计数区分合法 valid 间断与永久截断 → 等不到正确结算 → 外部复位清状态 → 也清掉正在排空的上一张完整输入帧 → 接入层若仍等待该结果就会出现未解释缺包。
优化与验收：先定复位边界与取消语义；新 session 清关联。若必须保存前一帧结果，再研究按帧隔离的排空/丢弃状态与有界元数据，不能只在 SOF 到来时粗暴清 RAM。异常不能复位或阻塞整条视频。
请专家建议：故障恢复时允许损失多少检测帧？是否有可靠帧结束/超时事件？是否接受维持当前简洁复位契约？

### 4.8 基础跟踪缺少观测年龄和重复身份防护【本次最小仿真确认】

事实：track 只在 result_strobe && result_valid 时推进确认/丢失；会话变化只在有效处理时生效；frame_id 目前用于输出身份，没有单调/去重检查。
链条一：持续无效结果或停止输入 → 不增加丢失计数 → 原 TRACK/HOLD 与 show 可一直保持 → 历史框可能被误认为仍是当前可靠观测。
链条二：同一有效结果被上游重复三次 → 三次都增加 ACQ 计数 → ACQ_FRAMES=3 可在只有一张独立图像的情况下确认目标。
本次在当前 RTL 最小仿真中，重复 frame=99 三次后进入 TRACK；随后 20 个无效结果仍 state=TRACK/show=1/frame=99。后两项发生在缺少上游保证的条件下，不代表已经观察到相机/CDC 故障。
优化与验收：保留“坏帧不是无目标”的语义，另设自最近有效观测的年龄/看门狗；明确去重和乱序防护在哪一层完成；采集重启要可靠清状态。LOST_FRAMES 数有效观测事件，不能直接当墙钟超时。
请专家建议：冻结画面/通信异常时应立即隐藏还是保留带年龄旧框？确认应依据独立帧数还是固定时间？MAX_JUMP 默认关闭，启用也需按实际帧间隔处理快移。

### 4.9 非法颜色参数的分类与结果标签不一致【本次确认的具体缺陷，尚未修复】

事实：分类器 TARGET_CLASS 只有 1/2 分别为绿/蓝，其余回退为红；原检测器和新 mask_stats 的结果标签直接取 TARGET_CLASS[1:0]。
链条：配置 TARGET_CLASS=7 → 分类实际按红色 → 全红帧 valid=1/present=1/count=4 → 结果 class=3 → 下游按标签解释时与实际像素判据矛盾。TARGET_CLASS=4/5/6 等还可能产生其他低位标签。
本次最小仿真同时确认旧检测器和新封装 class=7 参数输出标签 3；默认参数 0 的对照输出标签 0 正常。现有分类器夹取回归只检查 hit，不能证明完整结果包语义。
优化与验收：统一一个有效类别常量用于分类与发布，或在整个顶层明确拒绝非法配置；补 0/1/2 与越界/负参数的系统级结果标签测试。当前默认红色功能不因该边界问题失效。
请专家建议：工程偏好非法配置编译失败还是统一回退？标准须贯穿模块、模型、文字与文档。

### 4.10 资源及时序仍是独立 gate 结果【物理实现未闭合】

最终同一 RGB 测试架：旁路 918 LUT/579 reg/0 ERAM/0 DSP，过滤 1224 LUT/950 reg/1 ERAM20K/0 DSP；SWNS 1.170/1.140ns，HWNS 0.502/0.292ns。
链条：输入影子寄存器和输出选择器保留可观测性 → 报告含测试架且未含完整 track/文字/CDC/适配 → 真实连接的扇出、布局、RAM 和跨域约束不同 → 不能把当前面积当整机增量，也不能从人工 10ns 正裕量推导板卡 100MHz。
同架启用过滤较旁路多 306 LUT/371 reg/1 ERAM；这只是该测试条件下的差值。文字模块另有历史独立 282 LUT/194 reg，不能机械相加得出整机结果。
优化与验收：MAIN 明确 LUT/寄存器/ERAM/DSP 和实际时钟预算，完成真实顶层约束、P&R、setup/hold 与未约束路径检查；再比较 DSP/LUT/流水深度的取舍。
请专家建议：当前真正紧缺的是哪种资源或哪条路径？是否需要牺牲一些 LUT 节省 DSP？可以接受多少结果延迟？

### 4.11 更强候选分离的 4PPC 最坏吞吐尚未证明【高级算法硬件难点】

事实：只完成离线方法对照，没有部署连通域、多候选选择或高级时序关联；现有候选比较有弱桥、快移、遮挡碎片失败。
链条：组件分离需要行标签/等价合并/特征更新 → 四像素同拍可能触发多个关联与写冲突 → 棋盘、梳齿或大量短游程使事件率升高 → 不能反压的视频不会等待 → 没有处理能力与积压上界，有限 FIFO 可能溢出。
弱阈值补救又可能把不同目标通过弱桥相连；最大域可能选干扰物，精细网格减少误合并又增加存储。4 倍内部时钟也不能先假定能收敛。
优化与验收：先在有明确目标策略的序列模型解决弱桥归属、碎片重组与错误更新，再选精确 CCA/游程/网格；写清每拍最大操作、RAM 端口、活跃标签和队列上界；超界显式无效且不阻塞视频，并报告有效覆盖率。
请专家建议：能否限定最小间距、组件数、目标形状来换取有界硬件？更复杂方案在同预算下能解决哪些实际基线失败？

### 4.12 验证覆盖与工程收敛仍需提高【避免把机制通过当作交付】

链条：合成图容易逐像素给出精确期望 → 已覆盖窗口、边界、身份和复位 → 但缺少真实 ISP/传感器误差及 CDC/缓存竞争 → 单域稳定后查询文字也不覆盖直播扫描期间的更新 → 当前通过不能证明整机视觉稳定。
本次参数标签问题还说明：各模块分别通过，不代表跨模块的共同参数语义一致；两个 RTL 旁路对照还可能共同继承同一错误。
优化与验收：保留独立数学/集合 oracle、硬编码边界和故障变体；补系统参数一致性、重复/乱序/超时、结果晚到/覆盖、文字与框同帧测试；最终执行真实约束构建及长时间/剧烈明暗变化板测。
算法评价应分列误报、漏检、错误更新、历史年龄、取消率与恢复时间；未知标注不当无目标，取消不当漏检，重复控制不当独立样本。
请专家建议：最终验收场景、可接受失败率和数据规模是什么？研发拟定的指标需与使用目标及标注精度一起确认。

## 5. 后续优先级与决策门

1. 先修复已明确的系统参数标签一致性缺陷，并补小规模硬期望；确定 track 的去重/超时由模块还是适配层承担。无需等相机数据即可做。
2. MAIN 集中确认 EOF/abort/reset、真实时钟、结果事件、缓存身份、CDC、显示锁存、资源预算；用明确时序和异常例子冻结契约。先以过滤关闭的基线集成。
3. 等实际相机素材，明确最小目标与多同色语义；按场景拆分，验证基线，决定过滤是否值得启用。保持用户的保留意见，不先定生产阈值。
4. 基线真实主要失败已定位后，再推进 B 的候选分离和强弱关联；先解决序列模型反例和有界吞吐，再写 RTL。
5. 真实 P&R 与板测闭环：逐帧身份匹配、图文一致、恢复行为、长期稳定及资源/时序都达标后，才报告整机完成。
