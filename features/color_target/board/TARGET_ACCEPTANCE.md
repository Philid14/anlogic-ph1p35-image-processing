# TARGET 集成后的上板验收方法

日期：2026-10-20。**这是待MAIN接入并生成新bit后使用的测试方法，不是当前板测结果。**
当前独立交付入口：[MAIN_HANDOFF](MAIN_HANDOFF.md)。原视频bit没有TARGET，不能执行本页功能验收。

## 开始条件与证据

MAIN需给出新candidate tag、实际源码commit、全输入清单、归档bit/BUILD_INFO和SHA256，
明确TD含TARGET及对应适配器；保存同硬件配置下已批准的回滚bit。
沿用既有PROGRAM_SRAM流程，记录下载日志，不改传感器、白平衡、曝光、颜色阈值或support3。
按MAIN选定版本的按键说明操作，不假定控制版两模式与STYLE五模式相同。

至少记录板卡/摄像头/显示器与线材、供电、灯光、画面分辨率/刷新率，以及生产年龄/时基配置。
手机拍摄尽量同框包含真实物体、完整显示器、Logo和标注；录像记录时间点，固定手机曝光/白平衡便于比较。

若MAIN尚无可读的身份/诊断口，不自行新增引脚或UART。把以下缺项填“未测”，由MAIN安排经批准的采样通道：

| 必须能关联的信息 | 用途 |
|---|---|
| capture、DDR完整/取消、slot/generation、显示选帧及HDMI实际首像素key | 证明像素与身份一路对应，区分预取与实际显示 |
| box key、observation key、图文提交key、共同display_enable | 判断HOLD旧身份、整组提交和严格同帧门控 |
| capture_tick、显示时间/整扫描年龄、time_valid、epoch | 判断超时、停钟、恢复与首次显示统计 |
| guard拒绝/取消/超时计数、CDC溢出/丢失、FIFO/DDR错误 | 区分正常无目标、坏帧和链路失效；计数单位由MAIN定义 |

## 测试顺序与失败判定

每一步只改变一个主要因素。先做短测；持续黑屏、撕裂、冻结或错误计数增长时先保存证据并回滚，暂停后续画质比较。

| 项目 | 明确操作 | 应观察/验证 | 失败条件 |
|---|---|---|---|
| 版本与启动 | 核对bit SHA，下载后静置1分钟 | 正常出图、原Logo/模式文字完整；诊断初值和启动过程有记录 | bit身份不明、无信号、持续错位/复位 |
| 视频对照 | 相同场景比较回滚bit与新bit，按所选版本遍历原模式 | 四边和像素连续，模式与文字对应；TARGET不改变基础像素吞吐 | 仅新bit冻结/撕裂/花屏、S等稳态错误增长 |
| 出现与确认 | 单一较大红物体进入，固定机位/灯光，重复10次 | 可记录确认等待；按独立有效观测计ACQ，不按HDMI重复刷新计 | 没有新观测也累加确认，框/状态持续不一致 |
| 定位与移动 | 左→中→右各停2秒，再上下、斜向、快移 | 框覆盖红色区域，十字在包围框中点，坐标方向/量级正确；抓每个异常时间点 | 4像素周期错位、坐标倒向、旧框附在新像素上 |
| 图文原子性 | 在远隔两个位置间来回移动，录像并采样提交身份 | 框、十字、X/Y、count、state属于一次commit且扫描内稳定 | 新框配旧坐标/文字、半屏更新；仅肉眼正常不能宣称精确同帧 |
| 移出与重现 | 移出画面5秒再进入，重复10次 | 有效无目标与invalid/cancel不同；HOLD保留真实旧box key；不匹配像素时整组隐藏 | 把HOLD旧框改标新frame，或仅灭框而旧文字/底色仍当有效结果显示 |
| 无可靠结果 | 用MAIN批准的诊断方式停止可靠观测/结果，视频显示继续 | 超过已确认的整扫描年龄后整组关闭；重复显示不延寿，观察停钟也能失效 | 标注无限保留、到达时间刷新旧capture年龄；只遮镜头不能证明停钟 |
| session与异常恢复 | MAIN提供的受控采集重启/取消/CDC复位注入 | 失效期间整组关闭；旧I/O排空后新session恢复，旧包不复活 | 只清寄存器就复用忙槽，旧框/旧身份跨session回流 |
| 边缘/细条/干扰 | 目标触边、小物体、细条、两个同色物体分开记录 | 记录现有全同色区域合框限制，不先擅定最小尺寸或跟哪一个 | 超出边界、通道错位、把未决多目标需求宣称已支持 |
| 光照与长期 | 正常→暗→正常→亮→正常5轮，短测通过后运行至少30分钟 | 视频/Logo连续，恢复方式和时间可记录，错误计数不隐去 | 花屏/冻结/断信号、稳态错误累积、超龄标注未关闭 |

暗光漏检、红色反光或同色合框首先是场景/阈值证据，不自动判为DDR或CDC故障。
手机拍屏条纹需注明肉眼是否可见；原始RGB才适合像素级标定。
CNT递增不能证明相机活性；物体不动也不能证明没有重复帧。

## 系统故障注入不能省略

板上不具备安全注入入口时，以下项目必须由真实适配器RTL/多时钟仿真完成，并报告“板上未注入”：
重复/乱序frame、session重启、提前SOF/错误EOL/缺失EOF、最后拍/不完整尾拍、晚到/缺失结果、
DDR槽复用与读租约冲突、显示重复/跳帧、CDC单侧复位/在途包、图文不同观测及长期无可靠结果。
每项保留输入、字面预期、不变量和失败条件，沿用 [故障矩阵](../integration/FAULT_MATRIX.md) 与帧事务测试。
抽象测试架通过不替代真实适配器验证；视频无异常也不替代身份链证据。

按 [回报模板](TARGET_REPORT_TEMPLATE.md) 提交版本、完整操作、时间点、次数/分母、恢复方式和附件。
没有诊断支持时只报告“未观察到异常”，精确同帧、零丢帧/零溢出与端到端延迟继续填“未测”。
