## 3. A 级演示的讲解脚本（对着帧图讲）

按顺序打开产物目录里的 PNG，每张一句话：

1. `frame_01_appear.png` — 目标刚出现，**画面无框**：链路还没有任何结果。
2. `frame_02_confirm1.png` — 第 1 帧结果已消费，但 `ACQ_FRAMES=2` 还差一帧，仍无框。
3. `frame_03_track.png` — **确认完成，框出现；但红方块已经在右侧，框却画在中间**。
   不是算错：`detect` 在 `eof` 之后 1 拍才发布、`track` 在那一拍才消费，所以框在**下一帧**
   才生效。协议 §4.3 要求 MAIN 在帧边界把结果寄存一级，就是为了消掉这一拍差。
4. `frame_04_noise.png` — 目标回到中间并加椒盐噪声；画面上的框仍是上一帧的位置。
5. `frame_05_absent1.png` — **目标已经离开，框却几乎铺满画面**：框来自第 4 帧，那一帧的
   40 个孤立单像素噪点把包围框从 `60×60` 撑到了 `309×209`（`count` 3600→3640）。
   这是已知限制 2（本版本不做形态学滤波），也是"一次噪声会污染之后若干帧"的原因
   ——框只在"被接受"的帧更新，被撑大的框会被 HOLD 一直保持。
6. `frame_06_absent2.png` — 第 1 次丢失 → HOLD，框保持在被撑大的位置。
7. `frame_07_lost.png` — 第 2 次丢失到 `LOST_FRAMES=2` → SEARCH，框消失。
8. `frame_08/09_reappear*.png` — 目标重现，**重新走一遍确认流程**（不是立刻出框）。
9. `frame_10_cast.png` — 极端白平衡漂移：红目标的 hue 被推到 30.7°、刚越出默认 ±30° 窗口，
   本帧判无目标，而框停在上一帧的位置 —— 已知限制 4 的具体样子。

一句总结可以这么说：**"这套演示的重点不是'框很准'，而是六项自检把边界情况都钉住了，
并且我能把整条链路的行为逐像素画出来核对。"**

## 4. B 级演示：上板步骤（**待 MAIN 接入后执行**）

### 4.0 前置条件（逐项确认后才开始）

- [ ] MAIN 按 `INTERFACE.md` §10 的清单确认了接口（观察点、lane 排布、`sof` 来源、CDC 归属、叠加区域）
- [ ] `features/color_target/rtl/` 下的三个模块已加入 TD 工程输入列表（**由 MAIN 操作**，本角色不改 TD 输入）
- [ ] bit 已生成并通过上板自检（画面稳定、无花屏）
- [ ] 红线/红纸（目标）、绿色或蓝色物体（对照组）各一件
- [ ] 显示器已接 HDMI

### 4.1 步骤

| # | 操作 | 期望现象 | 失败时先查 |
|---|---|---|---|
| 1 | 上电，画面里**没有**红色物体 | 无框、无十字；状态行显示 `SEARCH`（若文字行已接） | 若一直有框 → 观察点是否取到了风格化后的流、`C_MIN` 是否偏小 |
| 2 | 把红色物体放进画面中央，停住 | 连续 `ACQ_FRAMES` 帧后出现绿色框 + 中心十字 | 框不出现 → `MIN_COUNT` 是否比目标像素数还大 |
| 3 | 缓慢左右移动红色物体 | 框跟随（**注意：框比目标慢一帧**，这是 §2.4 记录的正常现象，不是缺陷） | 框乱跳 → 画面里有第二块同色区域（已知限制 1） |
| 4 | 把红色物体移出画面 | 框**保持** `LOST_FRAMES` 帧后消失 | 框不消失 → `LOST_FRAMES` 太大 |
| 5 | 重新把红色物体放入画面 | 重新确认 `ACQ_FRAMES` 帧后框回来 | 立刻出框说明 ACQ 被改成了 1 |
| 6 | 换成绿色（或蓝色）物体 | 默认红色参数下**不响应**；把 `TARGET_CLASS` 改成 1（或 2）后响应 | 参数是否真的重新综合 |
| 7 | 用彩色纸/暖色光改变白平衡，让红物体偏橙 | 可能丢目标 —— 这是**已知限制 4**，如实说明即可 | 若很早就丢 → `HUE_HALF_WIDTH_DEG` 需按场景重新评估（**不得改主线 AWB**） |

### 4.2 降级方案（现场兜底）

- **文字行没接上** → 只用框 + 中心十字演示，口头报坐标（坐标可从 MAIN 的状态行或调试口读）。
- **跟踪不稳**（实板噪声大）→ 把 `ACQ_FRAMES` 调大（更稳、更迟）、`LOST_FRAMES` 调大（框更不容易消失）。
- **完全接不进主线** → 退回 A 级演示（跑渲染工具，用帧图讲），并如实说明"独立模块完成、模拟验证通过"。

### 4.3 现场话术（照念，不要拔高）

> "颜色目标检测是独立模块，已经过参数化自检和逐像素回归；**整机接入由 MAIN 完成**。
> 当前演示的是接入后的效果；如果哪一项没接上，我们会如实说明它还没通过整机验证。"

## 5. 排错

| 症状 | 原因 / 处理 |
|---|---|
| 提示"既没找到 Icarus Verilog，也没找到 ModelSim" | 按打印说明装 Icarus 或设 `COLOR_TARGET_MSIM`（详见 `README.md` §2） |
| `ValueError` / 转储里有 `x` | 仿真输出了未定态。先看是否改了参数到非法值（现已夹取，正常不会） |
| 自检报 `[与模型不符]` | 定位到具体用例名（脚本会打印），再用 `--locked-only` 缩小范围 |
| PNG 太小看不清 | 渲染时加 `--scale 4` |
| 渲染很慢 | 默认 320×240×10 帧约 10 秒；调小 `--width/--height` 或减少帧数（改 `build_scene`） |
