# 演示与实板验证步骤（2026-10-18）

| 演示 | 当前状态 | 操作入口 |
|---|---|---|
| 独立 TARGET | 现在可跑，合成输入和测试台显示 | [VERIFICATION.md](VERIFICATION.md) |
| 已归档完整视频 | 现在可对 EDGE_CONTROL_V1 做基线实板观察，不含 TARGET | [观察指南](board/OBSERVATION_GUIDE.md) / [回报模板](board/REPORT_TEMPLATE.md) |
| TARGET 整机 | 尚无接入后的 bit，等待 MAIN 契约/集成/构建 | 下述接入后验收 |

## 1. 独立演示

先按验证入口运行 quick 或 full，查看原始日志和 REPORT.md。重点展示 A1 修复前后差异、
36 条故障轨迹以及仍为 OPEN 的 TRACK 六缺口，而非仅截取 PASS 总数。
ModelSim 用 --sim modelsim --msim <win32aloem目录>，Icarus 依现有环境配置。

需要可视图像时：

```text
python features/color_target/render_color_target_frames.py --out <新输出目录>
```

历史渲染为 10 帧、192010 拍、768000 像素逐像素回归；是合成场景，不能证明相机精度或 HDMI 正确。
演示解释应同时指出：移动目标和框可能来自不同输入帧、40 个孤立点可撑大总包围框、HOLD 保留旧观测。
这些是当前直接接线测试架的限制，不是可接受整机的标准。边界寄存器只能固定扫描期输出，
同帧关联还需要可信 session/frame、DDR 代次与显示选择。

support3 是可选的中心支持机制，现有 RGB 封装默认关闭；孤立噪点改善不代表噪团和细目标均改善。
实拍未到前不把演示中的 MIN_COUNT/ACQ/LOST 或合成精度当作生产门限依据。

## 2. 现在的板测

使用归档完整视频版本，核对 bit 哈希和 BUILD_INFO；按观察指南执行启动、ORIGIN 静态、
真实运动、20 次模式切换、边缘阈值对照、明暗恢复和至少 30 分钟运行。
该 bit 没有 TARGET 框/十字/坐标，不能用它验收本次新功能。
CNT 持续变化只说明 HDMI 侧事件在变化，需配合真实物体运动证明图像更新。
回报版本、触发顺序、全屏/主体/OSD 现象、肉眼是否可见、视频时间点、复现次数/总次数与恢复方式。

## 3. TARGET 接入后再执行的验收

前提：负责人确认目标语义、最小目标/场景、允许检测延迟、历史最大年龄、取消恢复及资源/时钟预算；
MAIN 完成规范化/身份/CDC/显示提交并给出实际顶层验证、完整 P&R、bit/BUILD_INFO 唯一来源。
先对照基线跑通原图、算法、Logo、切换和长测，再执行目标场景。

| 输入 / 操作 | 独立预期与观察 | 判定失败或待测 |
|---|---|---|
| 确认无目标的背景 | 当前帧有效且无目标，不沿用别帧作为当前检测 | 错类/误框记录场景；不能直接归咎某门限 |
| 单目标出现、静止、左中右、移出、重现 | 按已批准 ACQ/丢失策略，记录框、十字、count/坐标/状态的观测身份 | 图文不同观测、框身份错误或年龄超限即失败 |
| 四边、最后像素、细条/小物体 | 像素级 gold 或已标注数字帧；含 EOF 最后一 lane | 仅手机拍屏不能证明最后 lane 或同帧，填未测 |
| 同色干扰、光照变化、快移 | 与已确认目标选择及实拍标注比较，保留误报/漏报 | 策略未定则为待决策，不凭主观选中就判正确 |
| 结果晚到/缺失、重复/跳帧 | 所选显示帧匹配；重复显示不增加独立观测；活动扫描不改组 | 借用最新框、拆包更新、无诊断丢失为失败 |
| 重启、截断、错误行标记、长期无可靠结果 | 取消账本完整，旧 epoch 不回返，视频继续且按已批年龄失效 | 无效帧伪装无目标、沉默无限留框、旧 session 回切为失败 |

“框慢一帧”不能无条件判正常。若采用历史显示，必须显式标明旧观测及年龄并满足获批上限；
若采用严格同帧，frame_key 不一致即不能显示。TRACK/HOLD 状态单独不足以证明新鲜度。
未经仪器/ID/计数器验证的丢帧、缓存溢出、精确延迟填写未测。异常先保留对照，按单一变量定位，
不同时改颜色阈值、曝光、滤波和跟踪参数来掩盖系统错误。
