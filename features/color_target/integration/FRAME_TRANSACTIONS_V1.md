日期2026-10-19。承接全项目重梳后的“可靠性→共同帧台账→严格同帧显示”路线。
**状态：可执行接口方案与测试已完成；MAIN适配器尚未实现，没有新整机P&R/bit/板测。**
本轮新增模型、测试台、运行器、来源校验工具与文档；未改生产RTL、MAIN或LATENCY文件。

## 1. 本轮推进了什么

没有重复原36条组件级契约轨迹。在其Key/Bundle语义上新增一个有界槽位事务模型，并将实际
`color_target_track_guard`、原track、框/十字覆盖器、文字覆盖器放入同一独立RTL测试架。

| 层次 | 本轮结果 | 适用边界 |
|---|---|---|
| 新联合帧事务模型 | 最终33/33字面预期 | 不模拟DDR像素、物理CDC或亚稳态；不实现MAIN |
| 生产TARGET联动 | 14类场景、187项硬检查通过 | 测试架提供抽象原子传输和显示调度，不能叫实际MAIN集成 |

| 原契约回归 | 36/36，10类故障 | 保留原始模型口径，不用它替代真实guard |
| STYLE构建来源 | 66/66输入绑定已闭合 | 原始历史构建来源复核，不是本轮重跑P&R；Gray约束缺口仍在 |

最终证据：[VALIDATION](../evidence/frame_transactions_2026-10-19/VALIDATION.md)。

## 2. 联合事务的职责

`model/frame_transactions.py`使用4槽、年龄200tick、扫描上界20tick作为测试夹具；这些不是
生产常量，也不把四槽数量冻结为永久接口。存活帧表受槽数限制；模型记录历史session集合
仅用于检查权威发行不复用，不是建议在RTL里保存无限历史表。

建议对象：

| 对象 | 必需语义 | 责任 |
|---|---|---|
| FrameRef | slot、递增generation、32bit session/frame、首像素capture_time | MAIN发行、完整传递 |
| FrameRecord | 写入中/完整/取消，结果是否已退休，可用标注，是否首次显示 | MAIN有界台账 |
| Annotation | 同一个观测的box/text/key/capture_time和准备完成状态 | TARGET字段＋MAIN文字事务适配 |
| Scan | 所选FrameRef、一次不可变标注快照、读租约、扫描起止上界 | MAIN显示选择与实际HDMI输出关联 |

实际generation位宽、时基和队列容量仍须MAIN根据回绕/吞吐/恢复界限确认，不由本模型替硬件选值。

### 正常过程

1. 新可信采集身份开始写一个可用槽；同session frame严格递增，重复/乱序/回绕拒绝。
2. 检测可能先完成，结果可以暂存；**检测完成不代表DDR已完成写入。**
3. 只有独立确认像素完整、拍/字数正确且无错误，才把该代次提交为可显示。
4. 显示选择时取得读租约、锁存身份与完整标注。文字未准备、结果缺失或整扫描年龄超限则整组隐藏，像素继续。
5. 在实际HDMI首有效像素事件再次检查整扫描年龄，并在这里计时/统计；读选择、预取和后来取消的选择都不能提前计入首次显示。
6. 扫描中不使用最新guard输出，不改文字输入；新结果等待后续显示边界。
7. 扫描结束后才释放租约。槽复用退休旧结果，旧generation包不能重新附着。

模型把`select`与`first_pixel`明确分开；重复的首像素事件不变成重复刷新。
预取等待可能耗尽标注年龄，因此在实际输出起点重查，不能只在DDR选帧时检查一次。

显示重复帧不增加独立检测次数；同一完整像素帧第一次实际显示计入延迟，再显示只报告图像年龄。
结果晚到后，只有该帧仍保存在可选槽中，才可能在下次同帧重复显示时呈现；此调度选项仍待MAIN确认。

### 写槽与读槽冲突

模型拒绝向读租约中的槽写新代次，记录带身份的`capture_dropped_reader_lease`。
这表示MAIN应另选槽或明确丢弃该采集事务，不是给摄像头返回ready或停顿像素。
不能先覆盖当前读槽，再用隐藏框掩盖已经被破坏的图像。

### reset与会话恢复

`start_session(..., old_io_drained=False)`只使元数据不可信并等待排空，保留旧读租约；
旧DDR读写、读预取、FIFO在途包及实际扫描不能因身份表清零而凭空消失。

只有MAIN证明旧事务已终结，调用已完成屏障的`old_io_drained=True`语义后，才开启新session。
单侧CDC reset、事件丢失或时基故障都必须使整组标注失效，直到可信恢复；清一个告警位不能恢复关联有效性。

这是假设需由硬件满足的契约。模型中的布尔drained并不证明现有DDR已经具备排空接口。

## 3. 生产RTL联动测试的实际范围

`tb/tb_display_transactions.v`实例化四个原有生产模块。观察时钟10ns，显示时钟14ns，
是刻意不同的仿真夹具，不冒充实际60/75MHz。`stage_annotation`任务代表一个明确假定的
原子传输完成事件；它不是同步器/FIFO，也没有替MAIN提供CDC硬件。

所有图形检查从公开输出端口读取：框线/十字命中与RGB，以及28个公开glyph字符请求。
坐标文字用字面字符串核对，例如A帧应为`RED X0110 Y100`、`N012345 TRACK `；
不读取文字模块内部BCD寄存器，也不以生产模型生成这些字符串预期。

现有文字没有观测ID/完成端口。测试架采用已记录的稳定输入140显示拍上界，再加一拍交接，
先准备、后提交；扫描期拒绝重新准备。该141拍是本测试架的保守安排，不是新生产延迟要求，
也不能假定真实消隐窗口足够。真实方案需选择已证明的blanking准备或经批准的shadow/commit接口。

覆盖：启动无结果；文字未准备；同帧框/十字/文字；新结果在扫描中到达；晚到结果只在边界生效；
槽位代次错误；有效无目标的HOLD保留真实旧box身份；重复/乱序/invalid/cancel/future及回绕；
会话切换和旧包；整扫描年龄；观察时钟停止；time_valid丢失；global reset。

### 必须独立于观察时钟的显示年龄

guard的clk停止时无法继续超时。测试架冻结观察时钟，让显示时钟继续，证实guard本身仍可能
保持usable；显示侧必须独立计龄并整组关闭，不能只接该usable位。

测试架按10/14ns夹具比例计算独立显示年龄，只是验证责任边界；其中乘除算式、直接读取的
参考tick/控制量都不是可复制进生产的CDC方案。MAIN需实现可信时基转移/显示侧watchdog及
新的epoch恢复协议。五号负对照故意让年龄随观察时钟冻结，触发硬断言。

### 五个负对照

| 故意破坏的测试架规则 | 最终失败检查数 |
|---|---:|
| 忽略slot generation | 2 |
| 扫描时直接使用最新guard框 | 3 |
| 忽略显示frame身份 | 2 |
| 没等文字准备就允许显示 | 2 |
| 观察时钟停止时冻结显示年龄 | 1 |

每个版本均完成全部14场景、187检查，vlib/vlog/vsim均退出0；预期功能失败明确保留，
不能把运行器最后的“负对照识别成功”误读成这些错误策略通过了验收。

## 4. 构建来源疑点的关闭

上一轮STYLE SDC哈希疑点已由精确字节证据关闭：第3–13行为CRLF，第1、2、14–17行为LF；
不改变任何约束命令即可重现归档SHA256 `457379c9...f5c0d`。

进一步读取实际构建commit042345的66项输入，并对Git blob/SHA256逐项验证。
三个官方参考文件也有混合换行：mc_to_user_interface、ph1p35_324_ddr_wrapper、hdmi_tx。
从用户已有原始Competition资料取得的字节与归档哈希精确相同，规范化LF后又与固定Git文件逐字节相同。
最终66/66输入来源闭合，**没有修改源码或SDC来凑哈希**。原先63/66的中间报告保留。

GitHub contents API对部分非UTF8文本会返回变换过的正文，本轮严格大小/Blob SHA检查拒绝它们，
再改用Git blobs API取得精确字节；未将这些工具数据差异算作RTL缺陷。

工具`tools/audit_build_source_manifest.py`仅允许精确SHA匹配的raw/LF/CRLF、
有界混合换行重建或“原始字节精确匹配＋LF内容等于固定Git”的证据，不转换编码或删除任意空白。

这只关闭输入追溯疑点。两组Gray max_delay仍Ignored、FIFO稳态和最新候选板测仍未关闭。

## 6. 复现

从仓库根目录，输出目录必须全新。工具位置用显式本机路径，不修改PATH/系统配置。

```powershell
python -B -X utf8 features/color_target/run_frame_transactions.py --out <新的模型目录>
python -B -X utf8 features/color_target/run_display_transactions.py --msim <ModelSim目录> --out <新的RTL目录>
python -B -X utf8 features/color_target/run_integration_contract.py --out <新的原契约目录>
```

来源审计命令及66项源下载/原始字节来源放在仓库外本轮输出目录，避免把整套厂商资料或另一工程线源码复制入TARGET。
本轮未运行Icarus、未重新运行全部RGB/字库/过滤综合回归；旧生产源不变，原证据保留。
