2026-10-19增补：用户已确认第一版严格同帧，以及TARGET独立guard；MAIN具体实现仍另行确认。
本草案保留原审计时的基线叙述，当前执行准备、排空/租约、显示时钟停止保护、
联合模型与生产RTL联动结果见[帧事务实施准备V1](FRAME_TRANSACTIONS_V1.md)。

状态：**供确认，未实现的适配器不能视作已存在。** 本轮未修改MAIN、track、text或support3。
审计源码基线 b4565a1，A1 本地修复 1e541f1 仅统一非法类别标签。
字段名称用于说明语义，不是已冻结的新增HDL端口。完整源码证据见 `ENGINEERING_AUDIT.md`。

## 1. 时钟与视频观察点

建议彩色观察点位于 AWB 后、风格化与DDR前OSD之前，96bit RGB888，4PPC，只读扇出。
lane0=[95:72]，每lane={R,G,B}；坐标为原图左上原点，x向右/y向下。
TARGET不接ready，适配/诊断失效不能反压、复位或停顿主视频链。

主线实际观察域是 `S_csi_rx_clk`，显示域是 `S_hdmi_pixel_clk`，DDR有独立域。
不能假定跨域源频相同或固定相位。历史STA频率只用于审计背景，集成须输出新的clock报告。

**纠正旧交接假设：**RAW侧uial2axis的tuser与该处有效像素对齐，不代表AWB侧user也对齐。
编译的根 `awb.v:303-307` 明确将 O_tuser=I_tuser 保留为提前通知；RGB/valid另有RAM和寄存延迟。
不得直接将 awb_O_tuser 接 TARGET I_sof，也不能改掉供video_in复位FIFO用的原提前通知。
MAIN可提供独立规范化sideband；若参考内部延迟标记，必须逐拍验证而非仅依据名字。

## 2. 规范化像素事务

| 字段/事件 | 契约草案 | 实施/检查责任 |
|---|---|---|
| pixel_valid/data | valid=1消费恰好4像素，无反压；间断期间坐标计数不前进 | MAIN适配；TARGET检查 |
| x0/y | x0=0,4,...,WIDTH-4；y=0..HEIGHT-1；与本拍RGB同来源 | MAIN提供；TARGET光栅检查 |
| SOF | 仅本帧首个有效拍，不是提前通知 | MAIN适配 |
| EOL | 仅每行最后有效拍 | MAIN适配；不能把任意valid下降沿当行尾 |
| EOF | 仅最后一行最后有效拍；与最终四lane一起采样 | MAIN生成并核实 |
| frame_key | session/frame整帧稳定、唯一、回绕前换session | MAIN发行/传递 |
| frame_abort | 已知坏帧不可发布有效测量；完整帧可送完并作废 | MAIN错误聚合；TARGET粘滞处理 |
| truncated/reset | 独立路径复位并新session重启；所有未发布结果取消 | MAIN控制并通知匹配器 |
| partial tail | V1无keep/lane_valid；不足4lane不在支持范围 | 解码/适配层拒绝或abort，不能静默填充成有效测量 |

WIDTH为4的倍数，坐标位宽足够，总像素数不超过20bit计数上限。固定配置更改需经过恢复屏障。
主线AWB的last由valid包络生成，若行内允许空洞将可能产生多次last，故需证明上游时序范围。
仅计满WIDTH×HEIGHT不能证明没有像素丢失/错位；还须使用包长度、实际帧结束、FIFO状态等独立错误来源。
目前顶层 video_in.I_mipi_rx_error 接0，不能当作已有真实错误汇总。

## 3. 结果完成、事件与取消

完整结果包含 frame_key、valid、present、class、count、bbox及框中心；框两端均包含。
valid=0 与 valid=1/present=0 语义不同。无目标/无效时数据字段为零，不表示检测到红色；
旧检测器无效结果身份可能沿用上帧，匹配层须依据可信帧事务账本判断，不能单独信任无效包ID。
A1统一class：1绿、2蓝，其余配置回退红且结果标签0；参数不代表物体ID。

| 独立路径 | 结果完成相对输入EOF | 后续处理 |
|---|---|---|
| 原color_target_detect | EOF采样沿后结果可见 | 下游下一拍消费 |
| 新封装旁路 | EOF+1观察时钟 | track再+1拍 |
| 新封装support3 | EOF+WIDTH/4+3观察时钟，1280宽为323 | track再+1拍 |

上述是完整支持输入且没有复位时的周期关系。不能只把RGB固定延迟323拍来对齐任意valid间断。
结果跨域服务、排队、文字转换和显示调度时间另计，必须分别使用各自时钟。
现有文字一次转换70拍、稳定新输入最多140拍可见；它允许合并中间更新，不是逐帧事件队列。

每帧需有一项可追溯结局：published-valid / published-invalid / cancelled / missing-diagnostic。
没有EOF不自动等于无目标。复位取消全部未发布结果，可能包含前一完整输入帧尾部；
若结果已发布而track未消费，复位仍会取消该次消费。接收方必须退休等待项，不能无限等待。
当前 O_protocol_error 是粘滞全局诊断；某后帧可先置位，不能据此否决较早健康帧，逐包有效位另判。

## 4. CDC整包与服务能力

MAIN适配器负责原子跨域；源端保持负载直到应答，或使用经过验证的异步FIFO。
脉冲两级同步、字段各自同步、异步读变化的时间戳都不满足整包要求。
reset源/目的任何一端必须形成epoch屏障，旧请求/应答及队列内容须完成或明确取消；
不能只清一个toggle后把旧状态解释成新事件。两端重新就绪前标注不可用，视频继续。

实现选择前给出：最大到达率/突发、最大接收停顿、传输/应答往返时间、服务率和容量。
充分的单邮箱条件示例：最大占用时间严格小于最小结果到达间隔，且无额外突发；
否则证明任意时间窗口的到达数减去服务数不超过容量。未知到达/服务上界时，不能宣称FIFO足够。
满时的策略必须批准并计数；模型采用整包显式丢弃仅作候选，不把它当作无丢结果实现。

## 5. DDR身份、选帧及扫描租约

建议元数据：`{slot_id,write_generation,frame_key,complete,invalid_reason,capture_time}`。
新写入代次开始先使旧内容退休；错误覆盖、回退和完整写入都须更新元数据，不只是写指针+1。
只有像素、字数与错误状态均确认完整，才提交该代次为可显示。
slot_id复用不能复用frame_key；同帧重复显示保留原frame_key及采集时间。

读出选择时锁存slot/generation/frame_key，并随读预取及像素流水到HDMI首有效像素。
必须证明扫描期间像素不会被新代次覆盖（租约/调度保证），或明确整显示帧无效；
单纯隐藏错误框不能修复已经被覆盖的像素。TARGET不能自行修改DDR调度。

结果按frame_key关联，槽代次用于防止已退休结果再次匹配。跳帧不虚构检测事件，重复显示不增加独立观测。
结果缺失/晚到不能借用“最新框”；晚到若缓存尚存可用于之后同帧重复显示，但这也是待批准调度选择。

## 6. 框、十字、文字的一次显示提交

建议初版采用严格同帧显示：选定像素frame_key与box/text/state/count的observation_key一致才显示。
若保留HOLD历史模式，必须显式携带旧observation_key/年龄/状态，不把身份改成当前帧。
这两个模式需要人工确认；独立模型采用严格同帧作为保守示例。

显示只在帧边界提交一组不可变字段，扫描期间不跟随“最新track”。
文字字段内部整组发布不保证与外部框同一显示帧；text当前没有观测ID/转换完成端口，
不能假定已能给转换后的字形标注身份。
MAIN可设计：在已证明足够的消隐窗口稳定输入，保证最坏转换结束后再提交框/文字；
或使用经批准的shadow/commit接口。现有text会自动检测输入变化，不得在活动扫描期随意改变其输入。
若窗口不足，应整组推迟或隐藏，不能让新框配旧文字。区域和Logo优先级仍由MAIN分配。

## 7. 时间/年龄/异常决策门

年龄方案与不变量详见 `TRACK_ADMISSION_PROPOSAL.md`，不能把模型夹具数值写入生产参数。
必须确认：目标语义、最小目标/场景、检测和显示延迟、历史框年龄、取消恢复策略、资源/时钟预算。
在这些条件未明确前，只完善基线系统闭环，不实施复杂候选分离或CNN；support3继续关闭。

完成顺序：MAIN确认契约 → 接线和断言 → 真实时钟/CDC/DDR/显示仿真 → 实际顶层P&R → bit来源归档 → 板测。
本草案、36条模型轨迹和当前特征测试只提供可执行的审查输入，不等同于这些步骤已完成。
