## 已确认问题

`frame_event_bridge.v`在full时禁止写入；cap_too_fast只由源间隔错误置位。
目的端暂停时，20个间隔5源周期的独立事件只交付16个，source/destination告警均0。
稀疏出队避免制造目的间隔告警；vlib/vlog/vsim退出均0，独立“交付或显式报错”不变量失败。

当前meter的evt_ready固定1，不能据此说正常运行已发生该故障；目的停钟、reset/在途数据和
极端服务中断仍需给出明确边界。满队列的不可见丢失必须补到异常契约。

## 最小修改建议与不变量

1. bridge对每次full丢事件产生可观察的loss/overflow状态；不向视频流反压。
2. 诊断本身安全跨域，不能异步采样变化的宽计数。单侧reset不能把旧请求/指针当新事件。
3. meter收到事件丢失后，使关联/统计失效；清告警位不能恢复有效性。恢复需显式resync/session屏障。
4. source的capture起点、完整帧commit、abort/overwrite分别定义；完整性尚未确认的帧不得计入有效主统计。
5. 与团队统一32/32 session/frame；回绕前换session，旧SID不能仅凭迟到数据重开。
6. 实际时基参数来自所选MAIN构建；固定出队补偿的±1拍结论须限定到达/排队/时钟假设。

不变量：任何丢事件都可见；错误关联不输出有效延迟；重复显示不重复统计；epoch切换后旧包不复活；
停钟与恢复不产生幽灵事件；异常诊断不能阻塞视频。
