## 1. 当前事实与风险

`rtl/color_target_track.v:81-97,144-159`：仅在 strobe&&valid 时更新；frame_id 用于输出，
未检查重复或单调顺序；session 变化由结果字段触发，且须有效 strobe 才处理。
没有时间输入、独立 session 控制或 age 输出。MAX_JUMP 默认为 0，启用时比较两个坐标轴距离，
不是按实际时间归一化的速度门控。

本轮真实 RTL 特征测试 `run_track_admission_audit.py` 留存九个采样：

| 注入 | 实际行为 | 评价 |
|---|---|---|
| 同一帧99重复三次，ACQ=3 | 进入TRACK、显示框99 | 独立观测次数保障缺口 |
| 帧3→2→1 | 进入TRACK、输出帧1 | 顺序保障缺口 |
| 确认后20次无效结果 | 仍TRACK、旧框3 | 无年龄机制；20不是生产超时要求 |
| 随后停止输入20时钟 | 仍TRACK、旧框3 | 无墙钟过期机制 |
| 新session的无效结果 | 旧session/旧框继续显示 | 没有独立重启控制 |
| 新session有效结果 | 从ACQ开始 | 已有正常路径控制样例 |
| 随后迟到的旧session有效结果 | 可再次切回旧session | 缺少session权威与旧包隔离 |
| 两次有效无目标，LOST=2 | 第一次HOLD，第二次SEARCH | 已有无目标策略控制样例 |

特征测试中的 trace_matched=true 仅表示复现当前行为；JSON 单列六个 OPEN_GAP，
不将它们标成需求已通过。重复/乱序是异常注入，不声称真实硬件已发生该故障。

## 2. 建议责任划分

| 责任 | 建议归属 | 原因与验证 |
|---|---|---|
| session发行、可信重启事件、采集帧号 | MAIN | 来源在真实采集/复位；TARGET不能从一包陌生SID猜测重启 |
| DDR代次、完整/取消/错误帧事件 | MAIN | 必须随真实缓存写入、覆盖、选帧管理 |
| CDC整包与复位代次隔离 | MAIN适配层 | 在信号跨域处证明保持、服务和取消；与LATENCY协调时基 |
| 最终身份去重/顺序准入 | 建议TARGET独立准入适配器 | 进入现有track前作防御检查，不把CDC恰好一次当作唯一保障 |
| 有效无目标计数、已有跟踪状态 | 现有TARGET track | 保持现有独立观测层含义 |
| 观测年龄和显示可用性 | 建议TARGET年龄输出＋MAIN显示门控 | TARGET给出观测来源/过期；MAIN在实际显示边界决策 |

备选：全部准入放 MAIN，TARGET 只提供断言；可以减少接口改动，但未来复用 track 时容易遗漏。
建议选择前者，先用独立适配器包住现有 track；**该生产适配器也属于其他RTL变更，需另行批准**。
具体模块边界、端口及谁承担诊断计数仍待双方确认。

## 3. 身份状态与不变量

前置条件：准入Key必须由可信MAIN事务账本关联，不能无条件信任旧detect的无效结果身份。
旧detect在某些孤立EOF上沿用前帧ID；无法可信关联时应报identity-unavailable并由取消账本退休，
不能用错误ID推进高水位而屏蔽后续真实帧。独立模型的Key是假设已满足此前置条件的输入。

- ID-1：`frame_key={session_id,frame_id}`；当前session由明确控制事件建立，不能由迟到数据包切换。
- ID-2：同session只准入严格递增帧号；相同帧号为重复，更小为乱序，二者不更新确认/丢失/框或年龄。
- ID-3：已消费的无效帧也占用该身份；随后同ID有效包不能“补写”同一观测。
- ID-4：帧号跳跃不虚构中间的无目标；丢帧计数、观测年龄和目标消失是不同统计。
- ID-5：帧号回绕前开启新session；同session的0接在0xffffffff之后必须拒绝。
- ID-6：新session控制立即清空身份准入、确认历史、历史框可见性和待匹配数据，不等待首个有效结果。
- ID-7：旧session包只记诊断/丢弃，不能切回旧session；复位或epoch切换必须覆盖在途CDC包。

参考模型为审计记录保存已见session集合，**不是建议硬件无限保存session历史**。
硬件可用当前epoch＋复位握手/排空屏障证明旧包已退休。session复用和32bit生命周期须由MAIN定义；
若整机重启使全部像素、队列、元数据同时失效，可另定冷启动规则，不能只清一个计数器。

## 4. 三种事件必须分开

| 事件 | 身份消费 | 跟踪意义 | 新鲜度意义 |
|---|---|---|---|
| 完整有效且有目标 | 一次 | 可增加独立确认/更新实测框 | 使用该帧可信采集时间更新正观测来源 |
| 完整有效且无目标 | 一次 | 按LOST策略增加无目标计数 | 证明链路有可靠观测，但不刷新旧目标框年龄 |
| 无效/取消帧 | 一次或由取消账本退休 | 不等于目标不存在，不增加目标丢失计数 | 不刷新可靠观测/目标年龄 |
| 长时间没有可靠结果 | 无需新结果事件 | 独立超时/STALE状态，不伪造无目标帧 | 本地可信时基仍前进，过期框不可冒充新观测 |

拟议诊断分列：duplicate、out_of_order、wrong_session、invalid、cancelled、timeout、queue_overflow。
是否增加显式STALE跟踪状态，或保持四状态并另给 stale/age/usable，待接口批准；
建议后者以减少对既有track状态解释的扰动。停止输入必须有独立tick，不能仅靠结果strobe驱动。

## 5. 时间与显示策略

建议以可信采集首有效像素的时间戳定义图像/观测年龄；实际时间戳位置仍需 MAIN/LATENCY 确认。
结果到达时间只能度量排队/服务，**迟到包不能使旧观测重新变新**。
不能跨域直接采样变化的宽二进制计数器；使用整包时间戳或经验证的共同参考时基。
若只有本地到达时间，只能报告到达后watchdog，不能声称完整图像年龄有界。

建议区分：最近可靠帧年龄、最近被接受目标的年龄、传输活性超时。
年龄过期时清除可见性/连续确认历史，但保持帧号高水位，防止旧包重新准入。
采集与显示时钟不同，所有阈值须标单位、频率依据、时基回绕与转换误差。

要同时满足“整显示帧不变”与“最大年龄不超界”，SOF处需检查：
`display_start + maximum_scan_duration - capture_time <= maximum_age`。
否则当前帧不显示该历史标注，或明确采用经批准的帧边界年龄量化规则。
不能在帧开始刚好未过期、扫描中途过期，却仍声称全过程满足同一严格年龄上界。

## 6. 未决参数，禁止直接写生产默认值

| 参数/选择 | 缺少的依据 |
|---|---|
| 最大历史框年龄Amax | 交互目标、帧率/丢帧、可容忍显示延迟 |
| 可靠结果watchdog | 相机帧间隔、允许停流/重启时长 |
| ACQ/LOST按有效帧还是连续物理帧 | 无效帧插入时业务含义；当前按有效结果 |
| session控制和CDC复位屏障 | MAIN实际复位域、队列与缓存生命周期 |
| 重复/乱序计数位宽和饱和 | 最大事件率、维护/读取方式 |
| 严格同帧或带年龄历史显示 | 项目演示需求；不能默默更改身份 |
| MAX_JUMP或运动门控 | 实拍速度、实际观测间隔；当前继续关闭 |

模型中的 age=5 ticks、acquire=2、lose=2、queue=2 都是小整数反例夹具，
不构成上述参数的推荐值。审批A2应先确认职责、事件语义和端口；阈值依据不足时保留未决。
