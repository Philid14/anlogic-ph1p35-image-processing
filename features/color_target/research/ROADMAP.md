# TARGET 下一阶段：选型标准、公开证据与对照试验

调研日期：2026-10-17。工程基线：`172815e97587c19a63863c27c1c86bc8e85353bd`。
范围：颜色目标的抗噪、候选选择与单目标跟踪研究。此轮未修改 RTL、默认参数或主线接口。

## 1. 当前结论

优先验证“保留流式颜色分类 → 比较轻量空间支持过滤 → 强候选优先关联 → 弱候选有条件补救”。
不能把最大连通域、放宽阈值或粗网格直接定为生产方案。

当前最值得深入的组合是：**两阶段强弱候选关联，加观测历史约束和可解释的拒绝更新机制**。
它借鉴成熟方法，但需要为本机 4 像素/拍、不可反压、有限存储重新设计。
连通域分离和单候选选择会改变现有“所有同色匹配像素共用一个框”的语义；须先由 MAIN
确认目标选择策略与结果契约，不能在原接口下悄悄替换。独立研究模型不代表该功能已交付。

已做 10 路离线比较。两阶段方法在若干弱颜色/已有目标先验案例有效，但在无强种子的弱桥、
快速弱目标位移和碎片目标上仍有失败，**没有一个原型达到下面的全部标准**。
因此此时应形成可证伪的优先级，而不是宣布全局最优或“首创算法”。

## 2. 我采用的选型标准

先过硬门槛，再用真实结果比较 Pareto 前沿。创新只在正确性、资源与稳定性合格后评价。

| 维度 | 本项目标准 | 当前证据/后续验证 |
|---|---|---|
| 流接口 | 连续接收每个有效拍的 4 像素；不反压、不丢 lane；行尾/帧尾最后 4 像素完整计入 | 新 RTL 必须给逐拍模型、全宽回归和最坏事件到达率证明 |
| 帧与坐标 | 结果绑定真实 session/frame；坐标对应原图；框中心仍是框中心；HOLD/预测不能冒充本帧观测 | MAIN 帧关联/CDC 尚未接入，不能填写已通过 |
| 资源与时序 | LUT/FF/ERAM/DSP、队列上界、延迟都须给实测；最终以 TD route 后 setup/hold 与 MAIN 预算为准 | 本轮 CPU 原型无 FPGA 资源/Fmax 结论；预算仍待 MAIN 确认 |
| 保留集质量 | 自定目标：已约定场景中 IoU≥0.9 的帧占比≥95%，中心 L1 误差 P95≤2 像素；同时报告漏检、误更新和像素保留率 | 这是研发目标，不是赛题条文或已实现指标 |
| 失败透明 | 单独列细目标、边界、同色干扰、碎片、弱桥、快速运动、完全消失与重现；不得只报平均值 | 本轮逐案例 CSV 保留全部失败；无目标场景单列误报 |
| 有界实现 | 证明每拍事件数量与处理能力；支持范围内 0 溢出，范围外显式无效且不阻塞视频；不能靠把难例全标无效“过关” | 全宽棋盘/梳齿/大量短游程/合并冲突是后续必要压力输入 |
| 可回退 | baseline 可复现；每个实验只改一个因素；新处理首先默认关闭；不可覆盖厂商 IP 或冻结版本 | 后续 RTL 实验沿 TARGET 目录并经原 PR/负责人审查 |
| 可解释创新 | 与同预算的简单方法消融对比；收益须超过测试不确定性，并说明新失败条件 | 不以模型新、星标多、论文 FPS 高代替本项目证据 |

最终整机验收另要求至少 2 小时连续观察和剧烈明暗变化下的稳定输出。这是本研究提出的
内部验收目标，需 MAIN 安排板卡测试，尚未执行。发生缓存/队列/身份异常必须计数并保留日志。

不对未实现方案编造“综合得分”。同样质量下优先资源更少、状态更少和验证更容易的方案。
如果高级组合没有稳定超过简单过滤，应采用简单方案。

## 3. 公开资料给出的可用路径与限制

下列仓库均通过 GitHub API 固定 commit，并读取了许可文件和相关源码；固定链接与哈希在
[`2026-10-17-source-manifest.json`](2026-10-17-source-manifest.json)。没有复制第三方实现进工程。
核查范围是所列文件，未审计全部依赖或权重。

### 3.1 成熟的流式形态学

[AMD Vitis erosion](https://github.com/Xilinx/Vitis_Libraries/blob/3ab1ecd20cf338b3f8f2824fdfeee115f3398889/vision/L1/include/imgproc/xf_erosion.hpp)
展示了行存储、打包像素和边界处理；所读实现有 NPPC1/NPPC8 分支。它依赖 AMD HLS 类型/工具，
不能直接作为安路 4PPC 模块。对本项目可借鉴的是窗口组织与边界验证方法，具体逻辑独立实现。

先比较三类：水平短游程剔除、3×3 中心像素支持过滤、开运算/多数滤波。
支持过滤只在中心已经命中时保留，不能把背景扩成目标；但密集小噪团仍会留下。
开运算会损伤窄物体，不能因为孤立噪点被清干净就忽略这类退化。

### 3.2 流式连通域

[LinkRunCCA 固定源码](https://github.com/Topi-ab/linkruncca/blob/a84d236c6e67b3ca511d4dfaa3a11ff605f057de/src/verilog/LinkRunCCA.v)
采用游程/链表式单遍统计，但顶层是单像素输入。它是架构参照，不能直接宣称满足本项目 4PPC。

[2021 年并行 CCL/CCA 论文](https://link.springer.com/article/10.1007/s11265-021-01636-4)
讨论了完整 4PPC 的多合并写冲突、暂停/缓冲处理，以及相邻像素 OR 简化。
这提示两个选型禁区：不能依赖反压；不能通过降低水平分辨率掩盖吞吐问题。

因此精确像素连通域暂列高收益/高验证成本路线。不得用“FIFO 足够大”代替最大到达率、
处理速率与积压上界证明。1PPC 核做 4 倍时钟或 2PPC 做 2 倍时钟也不能先假定成立；
需要真实时钟/TD 证据，且主线时钟改变属于 MAIN。

### 3.3 强弱两阶段关联

[ByteTrack 固定代码](https://github.com/FoundationVision/ByteTrack/blob/d1bf0191adff59bc8fcfeaa0b33d3d1642552a99/yolox/tracker/byte_tracker.py)
的价值在于先关联高置信候选，再有条件使用较低置信候选。
本项目提出的改造是：严格颜色候选优先；仅当没有可靠严格候选时，用放宽颜色条件的候选补救。
这是从框级跟踪向颜色候选的**工程类比与待验证假设**，不是 ByteTrack 原算法的 FPGA 实现。

不能先把强弱掩膜直接合并再找一个框，否则细弱桥会把两个强对象连成一块。
弱候选还应满足历史位置、面积变化、强种子归属与新鲜度约束；条件冲突时拒绝更新，
保留有年龄标记的 HOLD，不能把预测框标为本帧实测。

### 3.4 观测历史与运动门控

[OC-SORT 固定代码](https://github.com/noahcao/OC_SORT/blob/8462e7e729a93ccd3bd995c0a79a890336cb3a0b/trackers/ocsort_tracker/ocsort.py)
提供基于历史观测的运动关联思路。可在每帧结果层研究定点速度预测、方向一致性与随观测间隔
变化的搜索范围，无需把矩阵求解或复杂运算放进逐像素关键路径。

预测仅用于候选选择。对外输出的测量中心仍由真实包围框计算，不能偷换为平滑/预测坐标。
丢帧/中止后的时间间隔必须来自可信帧身份或时基；没有这些输入时只做明确标注的模拟研究。

### 3.5 2025 年视频分割新方法

[EdgeTAM 官方实现](https://github.com/facebookresearch/EdgeTAM/tree/7711e012a30a2402c4eaab637bdb00a521302c91)
与 [EfficientTAM 的 ICCV 2025 论文](https://openaccess.thecvf.com/content/ICCV2025/html/Xiong_Efficient_Track_Anything_ICCV_2025_paper.html)
表明视频分割中编码器和跨帧记忆都需要压缩。
这些是 PyTorch/模型推理路线，其端侧成绩不等于 PH1P35 上的可实现性证据。

本项目可研究少量可信结果元数据的保留、过期和重获策略；这只是设计启发，
不等同于神经模型的特征记忆/注意力。当前第一版不引入神经网络、模型权重或整帧缓存。
离线教师辅助标注属于后续可选研究，需要另行评估数据和任务范围。

## 4. 独立离线对照

运行：

```text
python features/color_target/research/compare_mask_routes.py --out <空输出目录>
```

160×120 二值强/弱掩膜，MIN_COUNT=64；22 个反例模板×4 固定种子，88 份评估输入，
10 方法共 880 次评价，实际有 34 份不同掩膜/先验哈希。部分无随机项模板跨种子重复，
**不是 88 个独立统计样本**；重跑得到的逐项 CSV SHA-256 与存档一致。
这是隔离“过滤/候选选择”的 CPU 集合模型；没有运行 RGB 分类、真实视频或 FPGA。
有历史先验的 warm 组提供一个固定的先前包围框，不是每帧喂真值跟踪器。
先验是理想化输入，不保证实际系统总能提供正确先验。

候选的数学口径：8 连通；支持过滤=中心为 1 且 3×3 至少 3 个命中；开运算=3×3 方形先腐蚀后膨胀；
多数滤波=至少 5/9；图像外补 0；网格候选需每格至少 4 个弱像素；历史关联门控为 L1 距离≤48
且框面积在先前框的 1/4..4 倍。上述数值为本次实验固定条件，不能当成生产推荐参数。

| 方法 | 单目标组 IoU≥0.9 /44 | 有弱色种子 /4 | 有先验组 /12 | 弱桥反例 /16 | 空场景误报 /8 |
|---|---:|---:|---:|---:|---:|
| 原始全局框 | 32 | 0 | 0 | 0 | 4 |
| 水平游程≥3 | 32 | 0 | 0 | 0 | 4 |
| 中心支持≥3 | 36 | 0 | 0 | 0 | 4 |
| 3×3 开运算 | 28 | 0 | 0 | 0 | 4 |
| 3×3 多数 | 24 | 0 | 0 | 0 | 0 |
| 最大严格连通域 | 40 | 0 | 0 | 4 | 0 |
| 弱域含强种子+关联 | 40 | 4 | 8 | 0 | 0 |
| 严格候选优先、弱候选补救 | 40 | 4 | 8 | 8 | 0 |
| 16×16 网格含种子+关联 | 40 | 0 | 0 | 0 | 0 |
| 8×8 网格含种子+关联 | 40 | 4 | 8 | 0 | 0 |

分组均值、像素保留率、中心误差 P95 和输入哈希见
[`结果摘要`](results/2026-10-17-mask-route-summary.json) 与
[`逐项 CSV`](results/2026-10-17-mask-route-results.csv)。空场景 recall 在脚本中约定为 1，
不能解释为真实召回率；空场景应看误报。缺失框的中心误差按 W+H 计罚，不把失败样本丢掉。

关键失败必须保留：

1. 开运算/多数滤波删除了细线；水平游程无法保留竖线。不能把它们统一当默认去噪。
2. 支持过滤能清孤立点，但 2×2/3×3 噪团仍可撑大全局框、造成空场景误报。
3. 最大域会选择更大的干扰物，且会丢掉被遮挡后分裂的目标片段。
4. 两阶段方法可避免“两个强对象被弱桥连接”的部分失败；目标完全变弱后仍可能误接到
   远处强干扰物。快速弱目标越过固定门控时也会漏检。
5. 粗网格会合并像素级本来分离的对象。16→8 的网格细化改善了本例结果，却增加存储，
   不能只挑 16 网格在单目标组较高的平均 IoU 宣布胜出。
6. 冷启动面对多个同色对象且没有选择规则时，没有信息能唯一决定“用户要哪一个”。
   该组单列，不能把实验中预设的目标位置当作可用算法输入。

尚未实现完整时序跟踪器，因此没有 IDF1、HOTA、遮挡恢复帧数或真实误更新率结论。
还没有真实 RGB 光照/白平衡测试，强弱掩膜结果不能证明颜色适应已经解决。

## 5. 值得探索的创新组合

目标是减少错误的“可信更新”，同时保持小存储和可解释性，而非堆叠算法名称。

候选结构：

```text
规范化 4PPC 彩色观察流
    → 严格/宽松两套无除法颜色判据（参数边界待数据验证）
    → 可选中心支持过滤（与完全旁路独立消融）
    → 有界候选摘要：面积、真实像素边界、强种子数、身份、溢出状态
    → 先关联严格候选；再对弱候选做归属/面积/位置/年龄一致性检查
    → 更新可信历史 / 显式拒绝更新与 HOLD
    → MAIN 按真实帧身份接入显示与文字
```

“严格优先”已在本轮模型中比较；种子归属、碎片重组、历史新鲜度及可综合 4PPC 摘要仍是
**未实现假设**。需要专门反例：弱桥有多个强锚点、目标完全无强种子、目标贴边/跨格、
突然转向、HOLD 后新对象占据原位置、采集丢帧与 session 切换。

强候选缺失时，弱候选越不确定，越应扩大不确定性并降低可更新性；不能一边无限扩大 ROI、
一边把“任何相近颜色”写进目标历史。重获应保留全图严格检索通路，避免只看 ROI 后永久丢目标。

只保存 2/4/8 份可信结果元数据的方案可做消融；预测只做门控，输出仍是本帧实测框。
这组工程组合的创新性要由相同硬件预算下的对照收益证明，目前不主张学术首创。

## 6. 硬件代价的先验估计（均未综合）

| 路线 | 可确定的存储下界/组织 | 主要风险 |
|---|---|---|
| 水平短游程 | 少量行内状态；必须暂存游程起点并处理跨 lane、行尾/帧尾结算 | 竖线/斜线被删；不能把 4 lane 各自当独立像素流 |
| 3×3 二值支持 | 至少两行 1-bit 存储，1280 宽时 2560 bit=320 byte，另有窗口/控制 | RAM 实际块数由端口/位宽决定；标签、坐标和 EOF 尾部冲刷须同延迟 |
| 3×3 开运算 | 两级窗口，行存储下界约 5120 bit=640 byte，不含控制 | 细目标退化、额外行延迟；不能在帧结束时丢掉未结算像素 |
| 精确像素 CCA | 行标签、等价关系、组件特征和合并状态；大小取决于明确的最大活跃标签数 | 4PPC 多写冲突与最坏吞吐尚未证明，不能从 1PPC 开源数字外推 |
| 16×16 网格摘要 | 80×45 格；若每格 count9+seed1+局部 bbox16=26bit，共 93600bit≈11.43KiB | 未计标签、队列和元数据；近邻对象被合并 |
| 8×8 网格摘要 | 160×90 格；count7+seed1+bbox12=20bit，共 288000bit≈35.16KiB | 质量/存储权衡；仍不等于精确像素 CCA |

网格数字只是一种假定字段布局的手算存储量，不是当前 Python 集合实现的内存，
也不是 TD ERAM 利用率。MAIN 未分配新预算前不能把这些资源当作可用余量。
不新增整帧缓存；4PPC 观察点、时钟、DDR 和共享 OSD 继续由 MAIN 维护。

## 7. 后续执行顺序与淘汰条件

1. **数据与任务定义**：向 MAIN 准备一份集中确认清单：目标选择规则、最小尺寸/形状、允许遮挡、
   帧尾/CDC/时钟、资源预算；建议取得至少 12 段 5–10 秒的正常/暗光/侧光/同色干扰/快移素材。
   尽量采集风格化之前的规范化 RGB；按场景、物体和光照拆分调参与保留集，不能随机拆相邻帧。
   此文没有代发消息或改变采集链路。
2. **低风险候选 A**：仅把中心支持过滤做成默认关闭的独立原型；与游程/开运算比较。
   如果噪点收益小或最小细目标退化，保留旁路，不为“去噪”标签强行启用。
3. **高收益候选 B**：先在序列模型中研究两阶段候选、弱桥归属和碎片重组，再决定精确 CCA 或网格。
   若仍误更新、需要无界状态或无法证明 4PPC 吞吐，停止 RTL 扩展，不改主线来迁就它。
4. **观测约束 C**：只在 B 明显优于基线后加入运动/新鲜度；分别关闭每项，量化它真正解决的错误。
   若更复杂方案不在同预算下稳定优于简单基线，采用简单方案。
5. **硬件收敛**：独立逐拍仿真→TD 综合/实现→MAIN 帧身份和显示适配→资源/时序复核→实板长测。
   每阶段分别报告状态，按原协议审查，不把 Python 对照、开源板卡成绩或独立模块冒充整机通过。

当前推荐是先执行 A 的数据验证，同时把 B 的两个未解决反例作为下一研究主线。
接口确认属于 MAIN，不阻碍 TARGET 继续做独立数据模型与候选验证。
