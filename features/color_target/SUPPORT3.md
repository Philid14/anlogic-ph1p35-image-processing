# 中心支持过滤：独立候选 A

状态：**独立二值掩膜实验，默认 ENABLE=0；未接入 detect/主工程，未生成 bit，未上板。**
这是 [研究路线 A](research/ROADMAP.md) 的可综合实现，尚未获得启用条件或 MAIN 资源预算。
旧检测器、颜色阈值和现有主线源文件列表不变；不是多目标选择或连通域实现。

## 数学定义与采用条件

输入掩膜 M；输出 K(x,y)=M(x,y) 且以 (x,y) 为中心的 3×3 命中数≥3。
图像外补 0，包含中心本身；不会把背景变成命中。掩膜 bit3 对应最左 lane0，bit0 对应 lane3。
与研究脚本的 support3 口径相同，RTL 未复制外部开源实现。

孤立点和孤立二连点被删；2×2 噪团全部保留。长的一像素水平/竖直/斜线会失去端点，
仅两个像素的孤立细目标会消失。先前 88 份输入/34 个不同哈希的 CPU 对照不是新实拍证据：
单目标组 IoU≥0.9 从原始 32/44 到 36/44，但空场景误报仍 4/8。
因此**不启用为默认算法**；最小目标尺寸/形状和真实 RGB 保留集确认后，再决定是否采用。

## 原型接口约束

`rtl/color_target_support3.v` 的输入/输出都是单时钟二值掩膜流，不含 RGB。
WIDTH≥4 且为 4 的倍数、HEIGHT≥1；坐标必须能由 XW/YW 表示。默认 1280×720、XW=11、YW=10。

| 条件 | 约定 |
|---|---|
| 默认 ENABLE=0 | 寄存一级透传全部字段；不实例化行 RAM；输出对应本次上升沿采样的输入 |
| ENABLE≠0 | 每有效拍恰好 4 个像素；从 (0,0) 开始完整、连续坐标光栅，可任意 valid 间断 |
| 标签 | SOF 仅首拍，EOL 每行末拍，EOF 仅帧末拍；session/frame 两个 32 位身份帧内不变 |
| 吞吐 | 无 ready；支持行间/帧间无消隐连续 valid，帧身份允许回绕和帧间 session 切换 |
| 输出顺序 | 原坐标从左到右、从上到下；零掩膜拍仍输出；标签与身份跟随中心像素 |
| 延迟 | 启用后需下一行及右邻拍；valid 间断会延长部分输出延迟；不能按固定拍数延迟 RGB 来匹配 |
| 帧尾 | 内部固定计数的末拍之后自动补零结算；无复位时，末输出 EOF 严格晚 WIDTH/4+2 个时钟 |
| I_frame_abort | 仅在 valid 拍采样，帧内粘滞；EOF 输出携带最终 abort，整帧统计必须丢弃 |
| 协议错误 | 坐标/标记/帧内身份错误置 O_protocol_error（复位才清）；该完整计数帧 EOF 带 abort |
| 截断/丢拍 | 不提供自动重新同步；中途丢拍、提前新 SOF 或尺寸改变后必须复位并从完整首拍重启 |
| 复位 | 清空有效状态和待输出尾部；不逐项清 RAM；第一行/图像外显式补零，隔离旧帧残留 |

启用模式内部以固定尺寸计数生成输出坐标/标记；不是把错误的输入标签“修复为有效帧”。
只有完整 EOF 且 abort=0 才能提交该帧统计。已经发出的部分掩膜不能作为整帧原子发布依据。
`O_protocol_error` 是附加诊断口，不是现有 TEAM 接口字段；该原型的截断恢复契约也比主接口严格。
MAIN 接入前仍须确认异常帧适配、观察点、帧身份、CDC 和显示匹配。不能直接插进现有 RGB 端口。

## 两行 RAM 与无消隐帧尾结算

两组 WIDTH/4×4 位同步 RAM 交替写入；当前拍发起读请求，当前输入的写入延后一拍。
一组给中心行，另一组给上行，当前输入给下行。一个待输出拍、三个位和下一拍首 lane 构成跨拍窗口。
EOL 直接以右侧零邻居结算，不等待下一个有效拍。

EOF 后，读调度器每个物理时钟处理上一帧末行的一个地址，下邻行强制为零。
下一帧第一行可以同时写入较旧的行缓存；不拿新帧首行当旧帧下邻行。
设旧 EOF 为 t，尾部第 j 个读恰在 t+1+j；新帧首行第 j 拍最早在 t+1+j 到达，
其 RAM 写入最早在 t+2+j，**读严格早于覆盖**。普通行同样先读地址 j，再于下一拍写入 j。
WIDTH=4 时，前一行只有一拍、最新中心数据可能仍在待写寄存器，显式转发该拍，
不依赖混合端口同址读写返回旧值或新值。新帧第一行至少占 WIDTH/4 拍，
尾读在第二行到达前结束，因此不需要 FIFO 或停顿，也不依赖视频消隐时间。
初版的同拍读写曾通过 RTL 仿真，却在厂商原语仿真中失败；最终结构特意消除这种依赖。

逻辑行存储为 2×1280 bit=2560 bit（320 byte），不含窗口和标签寄存器。
TD 可以把两组逻辑 RAM 合并到一个物理 ERAM20K，并不等于只分配 320 byte 的物理容量。
独立综合和厂商原语功能仿真证据见 [验证记录](evidence/support3_2026-10-17/VALIDATION.md)。

## 重现

```text
python features/color_target/run_color_target_support3.py --out <输出目录>/quick.json
python features/color_target/run_color_target_support3.py --geometry 1280x720 --out <输出目录>/full.json
```

仿真器通过现有 `--sim/--msim` 或环境变量指定。小尺寸测试穷举 512 邻域×4 个 lane 对齐位置；
独立 Python 集合模型不复制 RAM/窗口/调度器。默认旁路由 TB 每拍检查公开输出。
另覆盖随机 valid 间断、全 0/全 1、跨行/跨帧、末 lane、完整帧 abort、标签错误和复位清尾。

在空输出目录以正斜杠脚本路径运行 TD 的 `tools/synth_support3.tcl`：
默认顶层是启用过滤的 `support3_synth_top`；设置环境变量
`COLOR_SUPPORT_TOP=support3_bypass_synth_top` 获得相同观测架的旁路对照。
测试架用 3:1 输出选择器保证完整模块的每个输出可观测并满足封装 I/O 数量；报告包含选择器开销。
10 ns 约束只用于独立 gate 检查，未进行布局布线、真实主工程时序或 bit 验证。

为缩短原语仿真，可设置 `COLOR_SUPPORT_TEST_HEIGHT=3` 构建 1280×3 的同宽 RAM 测试网表，
再使用 `--geometry 1280x3 --gate-netlist <网表> --td-sim-dir <TD/sim_release>`。
厂商原语文件只读引用，不入库；短高度功能检查不能冒充 1280×720 的综合网表或实板验证。

下一步先用真实最小目标/噪声数据决定 A 是否值得启用；同时研究 B 的弱桥归属与碎片重组。
不因 A 的吞吐验证通过就跳过算法收益、资源预算和 MAIN 接口确认。
