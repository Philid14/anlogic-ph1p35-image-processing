# LATENCY_PERFORMANCE_V1 上板验收

候选完成后使用artifacts/bitstreams/LATENCY_PERFORMANCE_V1中的bit及BUILD_INFO核对SHA256。
首次用PROGRAM_SRAM，与track-region-fix-v1-candidate作同接线对照。这里提供的是待用户执行
的步骤，软件/RTL验证不代表已经通过实板验收。最终资源/时序以BUILD_INFO为准。

## 屏幕新增信息

透明面板位于左上Logo右侧(x256..639,y16..79)，不会增加图像流水拍数。

| 字段 | 含义 |
|---|---|
| LAT | 最近一次有效、首次显示某个采集帧的延迟，单位ms，两位小数 |
| MIN / MAX | 本次复位以来有效首次显示样本的最小/最大延迟 |
| AGE | 最近一个有效显示样本的图像年龄；重复刷新同帧时可增加 |
| NEW | 首次显示一个新的有效采集帧，更新LAT及统计 |
| REP | 再次显示同一帧；更新AGE，不把它重新计入LAT/MIN/MAX/N |
| BAD | 本次显示不能建立可靠完整同帧关联；数值保留上次有效结果 |
| WAIT | 尚未发布首个完整显示帧的统计 |
| F | 最近有效样本的RAW采集帧号，8位十六进制；BAD时保持上次有效值 |
| N | 有效、不同帧的延迟样本数，4位十六进制，FFFF饱和 |
| E | 无效测量样本数，4位十六进制，FFFF饱和；不是FIFO溢出计数 |
| 10US | 时间戳量化单位10us；不是宣称物理测量精度为10us |
| HEX | F/N/E使用十六进制，例如000A为10 |

计时起点是MIPI解码后的RAW首有效四像素拍，终点是该帧送入HDMI发送器的首有效像素。
不包含曝光之前、显示器内部延迟。参考为原有PLL实际配置75MHz，尚未做物理时钟校准。
显示结果在完整帧结束后才发布，因此F和LAT表示最近完成的有效样本，不是正在显示帧的即时标签。
此F是延迟适配器的RAW身份；不要与既有TRACK LAST FRAME的观察点计数直接相减。

## 最短功能检查

1. 重新烧录后等待约5秒。确认摄像头图像、安路Logo、CNT、原状态文字和透明延迟面板均出现。
2. 记录LAT/MIN/MAX、F/N/E和状态。启动阶段的未匹配帧可使E非零；重点是稳态E是否继续增加。
3. 再等30秒和120秒各记录一次。正常采集时F/N应继续推进，LAT应为有限的合理值；
   REP可由摄像头帧率和显示刷新率不同造成。不能仅凭REP认为丢帧。
4. BAD时不得把保留的LAT当作当前有效测量。若稳定视频下BAD持续或E持续增加，请记录完整屏幕及
   B/S、MODE、F/N/E；这会阻断“稳定延迟测量”的实板验收。

## 其他功能回归

- K3依次检查EDGE、ORIGIN、GRAY、BINARY、STYLE、TRACK、MOTION，顺序及K4语义保持原版。
- 开关仍使用原版配置，检查颜色对比、尺子标定、W/H和D/R、背景学习及目标框；没有新增开关功能。
- 对照旧bit检查画面位置、细线、白色边缘、原图色彩、字体、Logo、CNT、颜色框、尺寸标注与TRACK。
  新面板覆盖区域的新增字符是预期差异，其他图像算法应保持一致。
- 原有算法分支采用相同固定延迟，切换模式后LAT接近是预期现象，不要求数值明显变化。

## 稳定性与时序边界

连续运行至少30分钟；期间移动工件、切换全部模式、改变环境亮度并遮挡镜头。
遮挡镜头只改变像素内容，应继续产生采集帧；它不等同于断流实验。记录是否出现花屏、错行、
静止画面、BAD/E持续增加或原有B/S稳态计数增加。启动累计值与稳态新增值分开记录。

本版不声称解决所有既有FIFO/Gray约束覆盖风险。新的测量路径还需最终路由CDC证据和实板复核。
若参考时钟中断超过看门狗窗口，测量会保持BAD，必须复位/重新PROGRAM_SRAM后再验收；
参考时钟暂停期间无法建立绝对计时，不能把恢复后的旧时间戳当作可信样本。
手机拍屏可以核对字段和稳定性，不能单独证明0.01ms绝对精度；native测试的独立时间真值只覆盖模型边界。

回滚：重新烧录TRACK_REGION_FIX_V1归档bit，或恢复track-region-fix-v1-candidate源码/工程。
本轮不移动旧tag、不修改旧bit、不自动合并PR，不继续开发下一版算法。
