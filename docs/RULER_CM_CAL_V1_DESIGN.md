# RULER_CM_CAL_V1：厘米刻度粗标定

MAIN，基线123186a9 / VISION_TRACK_MOTION_V1 / Draft PR24；2026-11-01开始，2026-11-02继续。
用户接受大致比例，要求使用尺上厘米刻度像素间距平均；不再追求密集毫米刻度的严格判据。

## 已知事实与证据边界

- 用户拍屏显示1MM/R5/CAL FAIL；R5在代码中表示有对比度但未通过间距规则，区别于R6的帧完整性失败。
- 旧AREA规则：至少24个密集毫米间距、直方图一致性、两行100mm像素值相差不超过8px。
- 拍屏不能恢复真实RGB，不能证明对焦、光照、噪声、微小倾斜各自贡献；也没有通过bit SHA独立核验照片具体版本。不改写历史版本的板测状态。
- 本轮改变读尺口径，保留可靠回退；不把合成数字通过写成实物读尺已成功。

## 新算法与单位

沿用x256..1023、y192..479的768×288框，十二行缓存、27带重叠搜索；不新增图像缓存。
黑色公制厘米长刻线是操作前提，不进行OCR或单位识别。

1. 每行使用灰度最小/最大值，至少16级对比度。暗阈值=low+(high-low)/4，以偏暗笔画为主。
2. 提取未被框裁断、宽1..4px的细笔画中心。原坐标使用加倍中心，保留半像素宽度信息。
3. 搜索相邻标记12..120px的连续间距；相对首间距容差约25%+1px。至少五条标记，即四个以上间隔。
4. 行内按所有有效相邻间距的平均求比例，不依赖单个间距。两条相邻有效行允许约12.5%+1.2px/cm的差异，再平均两行结果。
5. 搜索完全部27带后选较大的稳定候选，避免先扫描到半厘米线就提前结束；两行证据来自同一完整捕获帧，不跨帧拼出一组刻线。
6. 输出仍为“每100mm像素数”的11bit接口，范围120..1200。不改变已有W/H、间隙和工程制图式标注换算。

若相邻厘米线平均d像素，则10mm=d像素，旧接口span=10d像素/100mm。
例相邻长线均值34px，span=340；工件宽170px对应50mm。
原有内部加倍中心公式为span=5×(末中心2-首中心2)/间隔数，带整数四舍五入。

这是粗比例尺，不是精密量具。显示0.1mm不等于0.1mm准确度。
假如厘米长线未显现，或框内有其他规律纹理，仍可能误认半厘米/其他节距；最大稳定周期是启发式，不能凭图像自行证明单位。
因此保留五线/两行/帧检查，不将任意黑点直接认定为厘米；成功后必须用一个尺量过的独立工件复核，排除倍数错误。
公制尺水平、清楚、至少五条厘米长线可见，平放干净浅色背景；摄像头正俯视且尺和工件同平面。

## 工程范围

仅两个正式HDL变更：ruler_area_calibration.v替换毫米直方图判据；engineering_dimension_marks.v的AREA标题改为1CM RULER LONG TICKS。
非AREA旧标题仍1MM。工程入口/引脚/PLL/SDC、视频/DDR/格式、Sensor/ISP参数、五算法、颜色对比、TRACK/MOTION、按键/开关和共享字体全部不变。
K4仍短按请求，整框读取约54个采集帧，保持尺子直到CAL:OK；不需要手工调span或另做X/Y两个步骤。
复位、重试、取消和异常帧处理保持：请求清校准有效位；错误帧R6不接受已缓存的候选；取消不确认；成功后关闭CAL继续沿用标尺测量。

## 数字验证策略

- 独立Python RLE/间距模型，构造真值要求span=10×厘米像素间距，显式防止模型与RTL共同误用半厘米/毫米因子。
- 原生RTL单元：19项/3992831周期，12..120px厘米距、33.4非整数距、毫米/半厘米/厘米混合、宽线、边缘、五线条件、抖动、平坦、无长线、错误帧、取消和复位。
- 完整实际读尺默认1280×720、768×288，框上/下位置共27443319周期，通过全27带搜索并得到500px/100mm。
- 整机ISP/原生ERAM/GSR/打包：9帧720p逐像素，当前标尺500px/100mm，透明字形和尺寸标注。为运行时间，仅把该整机测试的读尺搜索高度改为12；全部288搜索另由上述默认实例独立覆盖，不隐瞒这个边界。
- 8帧TRACK/MOTION及原按键/CDC回归，确认本轮不改变已有模式。
- 实际资源和最终时序以归档P&R为准；物理读尺成功率、粗尺度误差和长期稳定待用户上板。
