## 4. 真实RGB变化与AWB

公共算法比较区域去掉7内部横采样、7行halo，剩**50×18=900个内部点**，约100×18原像素覆盖；全RGB差异使用完整128×32 ROI。仅8帧、7个相邻变化，不把ROI各像素当作大量独立场景或长期样本。

| 指标 | AWB前 | AWB后 |
|---|---:|---:|
| RGB相邻帧平均绝对差，8-bit码值 | 1.91369 | 2.20299 |
| 分通道相邻MAE：R / G / B | 2.03355 / 2.09556 / 1.61196 | 2.41242 / 2.09556 / 2.10097 |
| 发生至少一个通道变化的RGB像素比例 | 99.4838% | 99.4838% |
| 逐像素时间标准差均值，ddof=0 | 1.56062 | 1.80310 |
| 单通道相邻差绝对值最大 | 24 | 24 |
| 全部样本通道最小/最大 | R19–41，G17–44，B12–32 | R20–45，G17–44，B15–41 |

99.48%是“至少一个码值不同”，不是99.48%画面出现明显运动。码值变化普遍而幅度较小，ORIGIN肉眼平稳不能据此视为数字逐帧相同。该暗部ROI没有可靠物体轮廓或独立运动/照明真值，不能把差异全部归为传感器噪声；照明、微小位移和前级ISP影响仍未区分。

这批码值变化相对暗部本身并不一定可忽略，MAE也不是上限；有最大24码值的相邻差。没有独立无噪声参考，未据此计算传感器SNR或宣称高模拟增益就是唯一原因。

## 6. 对根因和下一技术路线的判断

| 判断 | 证据等级 |

| 真实相机RGB存在细小帧间变化 | 本次完整CRC验证数据直接支持 |

| 四跳较旧版本放大抖动的实际倍率 | 本数据未激活连接，无法估计 |

1. 本次数据已完整保存。要换内容，必须重新触发采样；继续录当前101页只会重复这8帧。
2. 保持原曝光/模拟增益/BLC/AWB、灯光及FPGA相机固定。先用静止白纸与较暗背景形成一条**竖直或斜向纸边**，让边界穿过绿色ROI中央；两侧都占一定面积。之后再做眼镜框/文字局部，避免只拍到脸/背景的平坦区域。
3. 重新PROGRAM_SRAM同一candidate，立即K3进入ORIGIN确认绿色框；在600个实际SOF预热结束前定位并静止。若来不及，先定位好，再重新PROGRAM_SRAM，不靠采完后移动物体改变旧数据。
4. 最好同时保留一张绿色框穿过实际边缘的现场照片及场景/光源/是否静止说明。照片仅用于确认取景，不作为数值RGB输入。
5. 编码出现后沿用这次成功拍法：手机固定、完整白框及余量入镜，原始录像约4分钟。另存新文件，作为新burst独立解码，不与旧101页合并。
6. 代表性静态轮廓成功后，再安排慢速移动、出现/消失及不同光源的独立burst。8帧静态窗口不能验证拖影或长期效果。
