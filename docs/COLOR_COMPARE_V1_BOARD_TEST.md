# COLOR_COMPARE_V1 上板验收

本候选以已由用户确认能显示的EDGE_STYLE_FILL_V2为基线；未继承STYLE_V2_TARGET的事务缓存。实际bit、SHA、源码commit和资源/时序见新归档BUILD_INFO；没有归档成功时不得使用Runs中的旧bit。

## 首次操作

1. 保持原摄像头、HDMI、供电与接线，用`artifacts/bitstreams/COLOR_COMPARE_V1/camera_to_dsi_display.bit`执行PROGRAM_SRAM。
2. 初始仍为EDGE。按K3一次进入ORIGIN，确认真实摄像头画面、安路Logo、CNT、MODE/THRESHOLD/B/S仍在；K3顺序EDGE→ORIGIN→GRAY→BINARY→STYLE→EDGE不变。
3. 将标准色卡完全覆盖左侧绿色框**内部**（x256..383，y256..383）；待测物完全覆盖右侧青色框内部（x896..1023，y256..383）。每框采样128×128像素。边框外侧绘制，不参与颜色统计。
4. 等待至少两个摄像头完整采样帧。底部WAIT应转成REF/TEST/ABS/L1/MAX/LIM和颜色名称；LAST编号持续递增，表示最近完成的采样帧，16位自然循环。
5. 手机拍摄完整屏幕，拍清两框和四行数字；同时记录烧录版本、灯光、样品、运行时长以及是否存在花屏/冻结。

## 最有判别力的检查

- **位置及左右映射**：左红、右蓝，REF应偏红、TEST偏蓝；交换后两行RGB和色名应随之交换。某个RGB相等或相近不能单独验证lane顺序；本版每区使用全部四lane。
- **同色对照**：用同一张均匀、哑光色纸覆盖两框。记录REF/TEST及ABS，先评估灯光左右偏差。照明/镜头阴影会产生真实差值，不保证一定显示MATCH。
- **有色差样品**：左框固定标准色卡，右框依次放颜色接近和差异明显的样品；观察RGB、ABS、L1、MAX随样品变化，不只看MATCH字样。
- **空框与混合背景**：移开右框样品，数字应变成背景颜色，不能把它当“自动检测到物品消失”。本版不自动分割物体；任何背景、印刷字、反光都会参与均值。
- **模式独立性**：K3遍历全部五模式，测量仍应取原彩色输入；GRAY/BINARY/EDGE/STYLE的显示效果不应改变同场景真实颜色统计。K4仍只调整BINARY/EDGE原有阈值，不改变LIM:012。
- **运动与切换**：在TEST框内缓慢移动/快速撤掉样品，允许约一个采样帧的统计等待，不允许长时间保留错误结果；不得产生行错位或模式撕裂。
- **30分钟稳定性**：Logo/CNT及LAST持续工作，无花屏/冻结；记录B/S变化及明暗变化下行为。历史FIFO计数/Gray约束风险未修复，不能用仿真替代长时间实板结果。

## 数字解释

- REF/TEST：各自ROI的R/G/B均值，0..255。
- C：粗颜色类别，不是精细色名或材质识别。
- ABS：对应通道的绝对差，0..255；L1：三差之和0..765；MAX：最大通道差。
- MATCH：MAX≤12；DIFF：MAX>12。12仅为本版演示容差，不是标定的合格限，也不证明样品存在、材质相同或满足工业标准。
- LAST：本次结果来自前一完整采样帧，两个ROI为同一帧；面板与图像一起经过原DDR缓存。它不是DDR精确帧身份或处理延迟值。
- WAIT：启动尚未取得完整统计，或上一采样帧几何/计数无效；不将无效数据作为颜色结论。

这是相机ISP输出RGB的相对比较。初次测试优先在框架内使用均匀漫射光、哑光样品，避免高光饱和；不为了使MATCH出现而调Sensor或AWB参数。后续如需CIE Lab/ΔE与标准仪器比对，应另做光源均匀性、色卡及颜色变换标定。
